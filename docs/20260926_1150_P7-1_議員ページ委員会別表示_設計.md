# P7-1 議員ページ（Council Person Page）完了・委員会別表示 設計書

## 1. 概要・背景

「みらい議会＠世田谷区」をモデルとして推進してきた **P7-1 議員ページ（Council Person Page）** は、これまでに以下のフェーズを順次完了してきた：

- **Phase 7-A (#38)**: 議員一覧（`/councilors`）、議員詳細（`/councilors/[id]`）、会派・委員会所属・公式名簿外部リンクの表示、肖像権に配慮したイニシャル/モノグラムアバター（※後にP8-14でタイポグラフィ重視デザインへ更新）、本番インポーター整備。
- **Phase 7-B (#61)**: 質問要約連携（`council_member_questions`）、全38名・124件の代表質問・一般質問要約シード、議員一覧の質問件数バッジ、議員詳細のテーマタグ集計・AI要約カード・公式議事録リンク。
- **Phase 7-C (#66, #68)**: 議案詳細と発言・賛否議員との相互連携導線、会派アンカー（`#faction-{slug}`）、会派賛否データ投入。
- **Phase 7-D / P7-3 (#86, #88)**: 議員本人の公式X（旧Twitter）アカウント導線（確認済み28名登録、10名null）、安全な本番反映。

### P7-1 完了に向けた残課題
`docs/BACKLOG.md` の P7-1 Acceptance 1 および `docs/20260923_1630_議員ページ要件定義_世田谷モデル.md` の `REQ-2` において：
> - 議員一覧ページ（`/councilors`）で会派別・**委員会別**に新宿区議会議員（38名）の基本情報・質問集計を表示
> - REQ-2: 会派別・委員会別のフィルタリング・グルーピングができる

現状の `/councilors` は会派（`factionId`）別の絞り込みとグループ表示のみが実装されており、**委員会別のグルーピング・絞り込み表示**が未実装であった。
本設計では、`/councilors` に「会派別」と「委員会別」の表示切り替えと、委員会別のグルーピング・絞り込みを追加し、P7-1 をクローズする。

## 3. 要件仕様

### 3.1 表示切り替え
- 一覧上部に「会派別」「委員会別」の切り替えを置く（初期値は会派別）。
- `fieldset` + `legend` + `Button variant="ghost"` + `aria-pressed` で作り、見た目は既存の `chipClass`（高さ44px・`rounded-full`）を使う。
- `role="tablist"` は使わない。矢印キー移動と `tabpanel` の対応が要るうえ、リポジトリ内の既存トグルはすべて `aria-pressed` のため。

### 3.2 検索と絞り込みの state
- 氏名・ふりがな検索（`query`）は両方の表示で共有する。
- 絞り込みは表示ごとに分ける。会派別は `factionId`、委員会別は `committeeId`。
- 委員会別表示では `filterCouncilors` に `factionId: null` を渡し、会派別で選んだ会派フィルタが残らないようにする。
- 「会派 × 委員会」の組み合わせ絞り込みは今回入れない。

### 3.3 会派別表示（既存のまま）
- 絞り込みチップ「すべて 38」＋各会派（人数付き）。会派ごとのセクション（`#faction-{slug}`）。
- カード：会派内役職、期数、質問件数、常任委員会の所属。

### 3.4 委員会別表示（新規）
- **絞り込みチップ**：「すべて 38」（人数。既存と同じ表記で括弧なし）＋各委員会名と人数（人数は検索で絞る前の値）。
- **セクション**：委員会ごとに分け、`id=getCommitteeAnchorId(id)`（`committee-{id}`）と `scroll-mt-28` を付ける。見出しは委員会名（`lang="ja"`）、種別バッジ（`councilorDetail.committeeKinds`）、人数バッジ。
- **委員会の並び**：常任 → 議会運営 → 特別（`committee-kind.ts` の `KIND_ORDER`）、同じ種別の中は `sortOrder`。
- **委員の並び**：委員長 → 副委員長 → 委員（`ROLE_ORDER`）、同じ役職の中は議席順（`councilor.sortOrder`）。
- **件数表示**：重複を除いた人数と委員会数（「3委員会・1人を表示しています」／"1 councilor in 3 committees"）。延べ人数の合計は出さない。0件なら両表示とも `noResults`。
- **アンカー**はページ内でだけ使う。初期表示が会派別のため外部リンクの着地先にはしない（URL に表示状態を持たせるかは P7-2 の委員会ページと合わせて検討）。

### 3.5 委員会別表示のカード
- 会派名を出す（`lang="ja"`。会派がない議員は `messages.unaffiliated`）。委員会には複数会派の議員が混ざるため。
- その委員会での役職が委員長・副委員長のときだけ役職バッジを出す。委員は出さない。
- 会派内役職（幹事長など）と常任委員会の一覧行は出さない。同じ見た目のバッジが並ぶのを避けるため。
- 役職バッジの色は会派内役職の `bg-mirai-featured` と分け、コントラスト比 4.5:1 以上のトークンを使う。

### 3.6 多言語対応（i18n）
- 種別ラベルは既存の `councilorDetail.committeeKinds`、役職は `councilors.committeeRoles` を使う。
- 追加するのは `councilors.viewMode`（`legend` / `byFaction` / `byCommittee`）、`committeeFilterLegend`、`showingByCommittee(committees, people)` だけ。

## 4. アーキテクチャ

### 4.1 型（`shared/types.ts`）

```ts
export type CouncilorCommitteeInfo = Omit<CouncilorCommittee, "role">;
export type CouncilorCommitteeMember = { councilor: Councilor; role: CommitteeRole };
export type CouncilorCommitteeGroup = {
  committee: CouncilorCommitteeInfo;
  members: CouncilorCommitteeMember[];
};
```

### 4.2 純粋関数
- `committee-kind.ts`：`KIND_ORDER` を export、`ROLE_ORDER` を追加。
- `committee-anchor.ts`（新規）：`getCommitteeAnchorId(committeeId)` → `committee-{id}`。
- `filter-councilors.ts`：
  - `groupCouncilorsByCommittee(councilors)`：委員会のメタ情報は最初に出てきた議員の値を使う。所属のない議員はどのグループにも入らない。
  - `filterCommitteeGroups(groups, committeeId)`：null なら全件、指定があればそのグループだけ。
  - `countCommitteeView(groups)`：`{ committees, people }`。people は議員 ID の重複を除いた数。

### 4.3 コンポーネント
- `councilor-card.tsx`：props に `committeeRole?: CommitteeRole`。指定があれば委員会別表示として描く。
- `councilor-list-view.tsx`：`viewMode`・`factionId`・`committeeId`・`query` の state を持つ。セクションは `faction-list-sections.tsx` と `committee-list-sections.tsx`、チップ群（表示切り替え・会派・委員会）は `filter-chip-group.tsx` に分ける。
