## 手順と証跡

### 1. `.env.production`（ローカル、コミット対象外）

作業開始時のファイルには `SUPABASE_URL`、`SUPABASE_SERVICE_ROLE_KEY`、
`CHAT_DAILY_COST_LIMIT_USD`、`NEXT_PUBLIC_WEB_URL`（`http://localhost:3000`）
しかなかった。`admin/src/lib/env.ts` は `NEXT_PUBLIC_SUPABASE_ANON_KEY` がないと
起動時に例外を投げるため、このままでは `pnpm dev:admin:prod-db` が動かない。

次のように直した。

- `NEXT_PUBLIC_WEB_URL` を本番Webに変更
- `NEXT_PUBLIC_SUPABASE_URL` と `NEXT_PUBLIC_SUPABASE_ANON_KEY` を追加（Supabaseダッシュボードの値）
- `REVALIDATE_SECRET` を新しく生成（64桁のhex）。Vercelのwebプロジェクト（Production）にも同じ値を入れて再デプロイした

`.env.production.example` にはすでにこの5キーが載っている。

### 2. 本番 `/api/revalidate`

```bash
set -a; source .env.production; set +a
curl -s -X POST https://miraigikai-shinjuku-web.vercel.app/api/revalidate \
  -H "Authorization: Bearer $REVALIDATE_SECRET" \
  -H "Content-Type: application/json" \
  -d '{"tags":["bills"]}'
```

- 再デプロイ前: `401 {"error":"Unauthorized"}`。Vercelの環境変数は再デプロイするまで反映されない
- 再デプロイ後: `200 {"success":true,"revalidated":true,"tags":["bills"],"timestamp":1790249729832}`（2026-09-24 20:35:29 JST）

APIは `tags` だけを見る。実装計画の例にあった `"paths":["/"]` は無視される。

### 3. 本番DB接続のAdmin

ポート3001ではローカルDB接続のAdminがすでに動いていたため、
`ADMIN_PORT=3011 pnpm dev:admin:prod-db` で別ポートに立てた。

最初はログインできなかった。`admin@example.com` を作るのはローカル用の
`supabase/seed.sql` だけで、本番にはAdminアカウントがない。本番で使うには、
Supabaseの Authentication でユーザーを作り、`raw_app_meta_data` に
`{"roles": ["admin"]}` を付ける必要がある（ロールはログイン時に読まれる）。
これを済ませたあとはログインでき、議案一覧が本番DBの内容で表示された。

### 5. レイアウト

4件なので、`getFeaturedBillLayout` の規則では先頭が全幅の主役カード、
残り3件は2カラムに並び、奇数の最後の1件が全幅になる。本番のHTMLでも
`md:col-span-2` が2か所（主役と最後の1件）にあり、主役カードに `md:p-8` と
`md:text-2xl` が付いていた。スマホ幅（DevToolsのデバイスツールバー）では
1カラムに積まれ、崩れはなかった。

## 検証中に見つけたこと

- **注目の議案がタグ別一覧にも出ることがある。** タグ別一覧は、
  タグの議案が4件以上のときだけ注目の議案を除外する。3件以下のタグでは注目の議案も
  そのまま並ぶため、同じカードがトップページに2回出る。BACKLOG P8-13に登録した
- **タグ別一覧の3件はランダムに選ばれる。** 1会期23件程度では、固定の順序のほうが
  毎回同じものが見られる。BACKLOG P8-14に登録した
- Claude CodeからのPOST（`/api/revalidate`）と本番DBへの読み書きは、権限分類器に止められる。
  本番に触る操作は運営者が手元で実行した
- 本番DB接続のAdminはサービスロールキーで本番を書き換えられる。確認が終わったら停止する
