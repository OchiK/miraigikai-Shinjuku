# デザインシステム定義 — Organic

みらい議会＠新宿区の見た目を決める取り決め。色・文字・余白・部品・画面構成をここに集約する。実装時はこの文書と `web/src/app/globals.css` のトークンだけを参照し、スクリーンショットから色や寸法を推測しない。

視覚的なリファレンスは別途 HTML のスタイルガイドがある（`Shinjuku Design System.dc.html`）。矛盾があればこの文書を正とする。

---

## 1. なぜこの見た目なのか

公式資料は正確だが、読み手を選ぶ。このサイトは公式情報を置き換えるものではなく、公式情報への入口として働く。だから見た目も「行政文書の続き」ではなく「人が読むもの」に寄せる。

基調は行政色の青ではなく、クリーム（#f5ead8）とテラコッタ（#c67139）。角は丸く、余白は広く、見出しは左に揃える。区内には51,870人の外国人住民が暮らしている（2026年8月1日）。日本語の行政文書を読み慣れない人が最初に受け取る印象を、硬さではなく温度にする。

### 三原則

1. **入口であって、置き換えではない。** どの画面からも公式ページに1タップで戻れる。AI生成部分は必ず出典と併記し、視覚的にも一次資料と区別する。
2. **カード1枚で「何が決まるのか」。** 議案カードは題名・状態・要約・分野の4つだけで完結させる。
3. **日本語が母語でなくても迷わない。** 言語と難易度の切り替えは、どの画面でも同じ位置・同じ形。

## 2. 色

実装は `handoff/globals.organic.css` を `web/src/app/globals.css` の該当ブロックに差し替える。

### 役割

| 役割 | トークン | 値 | 用途 |
|---|---|---|---|
| 地 | `--color-mirai-ground` / `--background` | `#f5ead8` | ページ全体。白は使わない |
| 面 | `--color-mirai-surface` / `--card` | `#ebddc5` | 議案カード、入力欄、モーダル |
| 沈んだ面 | `--color-mirai-surface-sunken` | `#eee7db` | 前回の定例会などのアーカイブ領域 |
| 文字 | `--color-mirai-text` | `#201e1d` | 本文。黒ではなく温かい墨色 |
| 主アクセント | `--color-mirai-accent` | `#c67139` | 主ボタン、選択状態、注目 |
| 副アクセント | `--color-mirai-accent-2` | `#7a8a5e` | 可決など確定した結果 |

### 階調

`--color-neutral-100…900` / `--color-terracotta-100…900` / `--color-sage-100…900`。OKLCH の共通明度スケール上で生成しているので、どの系統でも同じ段は同じ視覚的重さを持つ。

- 100–300 … 塗り、ホバー、やわらかい境界
- 500 … その系統の基準値
- 700–900 … 塗りの上の文字、押下状態

**色は必ずこの段から取る。** その場での `color-mix()` や新しい16進数を足さない。

### コントラスト

テラコッタと地の対比は約3:1。アイコン・大見出し・UIの縁には使えるが、本文サイズの文字には足りない。本文に使う場合は `--color-mirai-accent-text`（terracotta-700, 約7:1）。

補助テキストの `--color-mirai-text-muted` は neutral-700 で、地に対して4.5:1 を満たす。それより明るい段を本文・補助テキストに使わない。

### 議決ステータス

Organic に赤は無い。議決結果の表示だけは拡張として追加している。

| 状態 | 文字色 | 背景 |
|---|---|---|
| 可決 | `--color-status-passed` `#56633f` | `--color-status-passed-bg` `#e1eecc` |
| 否決 | `--color-status-rejected` `#9c3527` | `--color-status-rejected-bg` `#fae0da` |
| 継続審議 | `--color-status-continued` `#8c491a` | `--color-status-continued-bg` `#ffe1d0` |
| 審議中 | `--color-status-review` `#645c50` | `--color-status-review-bg` `#eee7db` |

**色だけで結果を伝えない。** 必ずラベル文字列と併記する（`getBillCardStatusLabel` の出力をそのまま表示する）。

## 3. 文字

Caprasimo は日本語の字形を持たない。欧文の表示体はそのまま残し、和文には同じ丸みを持つ Zen Maru Gothic を対にする。本文は Figtree と Zen Kaku Gothic New。1つの `font-family` に両方を並べれば、和欧混植でも自動で切り替わる。

### `web/src/app/layout.tsx` の差し替え

```tsx
import {
  Caprasimo,
  Figtree,
  Zen_Kaku_Gothic_New,
  Zen_Maru_Gothic,
} from "next/font/google";

const figtree = Figtree({
  variable: "--font-figtree",
  subsets: ["latin"],
  weight: ["400", "600", "700"],
});

const zenKaku = Zen_Kaku_Gothic_New({
  variable: "--font-zen-kaku-gothic-new",
  subsets: ["latin"],
  weight: ["400", "500", "700"],
});

const zenMaru = Zen_Maru_Gothic({
  variable: "--font-zen-maru-gothic",
  subsets: ["latin"],
  weight: ["400", "500", "700", "900"],
});

const caprasimo = Caprasimo({
  variable: "--font-caprasimo",
  subsets: ["latin"],
  weight: ["400"],
});

// <body className={`${figtree.variable} ${zenKaku.variable}
//   ${zenMaru.variable} ${caprasimo.variable} font-sans antialiased`}>
```

`Noto_Sans_JP` と `Lexend_Giga` は削除する。`viewport.themeColor` は `#c67139` に変更する。

### 大きさの段

Organic の段をそのまま使うが、**本文だけ 15px → 16px、行間 1.55 → 1.9 に上げる**。日本語は字面が大きく、行間が詰まると読めない。

| 役割 | 書体 | サイズ / 行間 | 使う場所 |
|---|---|---|---|
| H1 | Zen Maru Gothic 700 | 42 / 1.28 | ページ題名 |
| H2 | Zen Maru Gothic 700 | 32 / 1.3 | セクション（注目の議案 ほか） |
| H3 | Zen Maru Gothic 700 | 25 / 1.4 | タグ見出し |
| カード題名 | Zen Maru Gothic 700 | 20 / 1.5 | 議案カード |
| 本文 | Zen Kaku Gothic New 400 | 16 / 1.9 | 要約、説明 |
| 補助 | Zen Kaku Gothic New 400 | 13 / 1.75 | 日付、注記 |
| ラベル | Caprasimo 400 | 11 / 1.2 · +0.1em | キッカー、英字ラベル、会期年号 |

**Caprasimo を日本語に使わない。** `font-display` は英数字のみ。

### 難易度とルビ

| 段 | 1文の上限 | 行間 | 備考 |
|---|---|---|---|
| easy（やさしい日本語） | 40字 | 2.0 | 漢字にルビ、分かち書きあり |
| normal（ふつう） | 60字 | 1.9 | |
| hard（くわしく） | 制限なし | 1.9 | 法令用語可、初出に注記 |

段が変わっても行の高さは変えない。ルビが付いても行数が増えないよう、要約のクランプは行数ではなく高さで固定する（既存の `RubySafeLineClamp` を維持）。

## 4. 余白・角丸・影

### 余白

1.10倍の密度スケール。`--space-1` 4.4 / `-2` 8.8 / `-3` 13.2 / `-4` 17.6 / `-6` 26.4 / `-8` 35.2（px）。カード間は space-4、セクション間は space-8 の2倍。

丸い形は空気がないと硬く見える。詰めるより空ける。

### 角丸

| トークン | 値 | 用途 |
|---|---|---|
| `--radius-sm` | 8px | 画像、小さな塗り |
| `--radius-md` | 16px | 内側のブロック |
| `--radius-lg` | 28px | 大きなコンテナ |
| `--radius-xl` | 32px | 議案カード、モーダル |
| `rounded-full` | 999px | ボタン、タグ、入力、セグメント |

**直角は作らない。**

### 影

`shadow-mirai-sm` = カード、`-md` = 固定ヘッダー、`-lg` = モーダルとチャット。3段より上は作らない。ホバーで影を動かさない（地色を1段暗くする）。

## 5. レイアウト

読みの主役は1本の縦カラム。スマートフォンでの1分の閲覧を前提に、段組みは作らない。広い画面では中央のカラムを保ったまま、議案詳細に限り右側にチャットを置く。

| Breakpoint | Min width | 変わること |
|---|---|---|
| base | 0 | 1カラム。左右余白16px。チャットは議案詳細の末尾から遷移 |
| `sm` | 500px | 左右余白24px。カード内画像が高くなる |
| `md` | 700px | 本文カラムを700pxで固定し中央寄せ。上余白96px |
| `pc` | 1000px | 議案詳細のみ、右に500pxのチャット列。本文カラムは動かさない |
| `pcl` | 1400px | 全体を1440pxで止める。それ以上は余白 |

既存の `MainLayout`（`max-w-[700px] mx-auto md:mt-24`）と `Container`（`max-w-4xl`）はそのまま使える。`sm:shadow-lg` は `sm:shadow-mirai-md` に置き換える。

ビューポート高さは `dvh` を使う（`h-screen` / `min-h-screen` は禁止）。詳細は [スタイルガイド](20260220_1530_スタイルガイド.md)。

## 6. 部品

既存の `@/components/ui/*`（shadcn/ui）を土台に、上記トークンで色を差し替える。新しい部品クラスは作らない。

### ボタン

`Button` の variant を3つに絞る。

- primary … `bg-primary text-primary-foreground`、hover `bg-primary-accent`、押下 terracotta-700
- secondary … 枠線 `border-mirai-border`、hover は地の上に neutral の薄い塗り
- ghost … `text-mirai-accent-text`、hover は terracotta-100

高さは最低44px。1画面に primary は1つだけ。

### 分野タグ

`bg-mirai-tag text-mirai-tag-text rounded-full`。**分野ごとに色を振らない** — 分野が増えても破綻させないため。注目だけ `bg-mirai-featured text-mirai-featured-text`。

### 難易度セレクタ

やさしい / ふつう / くわしく の3択セグメント。`rounded-full`、選択中は `bg-mirai-level-active text-mirai-level-active-fg`。ヘッダー右に常駐し、位置を変えない。切り替えても本文のスクロール位置は保つ。

### 言語セレクタ

対応7言語（`ja` / `en` / `zh-Hans` / `ko` / `ne` / `my` / `vi`）を**折りたたまずに横並びで見せる**。これがこの区のサイトの署名になる。選択中は枠線タグ、未選択は neutral タグ。

### 議案カード

このサイトで最も多く現れる部品。上から順に固定し、順序を入れ替えない。

1. 画像（任意） … 16:9。無い場合は詰めるだけで代替図形は置かない。`.washed` で地に沈める
2. 題名 … Zen Maru Gothic 700 / 20px。AIが付けた読める題名。正式名は詳細ページで出典と並べる
3. 議決ステータス + 掲載日 … ステータスは色+ラベル。日付は `--color-mirai-text-muted`
4. 要約 … 4行で切る。高さ固定のクランプ
5. 分野タグ

- カード全体がリンク。中にボタンは置かない
- ホバーは地色を1段暗く、影は動かさない
- **枠線は使わない。** 現行の `border border-black` を削除し、`bg-card` + `shadow-mirai-sm` + `rounded-xl` に置き換える
- 一覧ページでは画像なしの詰めた版（`CompactBillCard`）を使い、1画面に3枚以上入るようにする

## 7. 画面構成 — トップ

上から：

1. **固定ヘッダー** … 地の上に浮く丸角バー。左にサイト名、右に難易度セレクタとメニュー
2. **ヒーロー** … 新宿の街のひきの写真（`.washed`）。「いま新宿区議会で議論されていること／やさしい言葉で説明します」を1文で。装飾の見出しは置かない
3. **開会中の会期バンド** … `bg-accent text-accent-foreground`。会期名と日程。**1つだけ。** 閉会中は neutral に落とす
4. **注目の議案** … H2 + 補足1行 + カード。絵文字は使わない
5. **タグ別セクション** … タグごとに H3 + 説明 + 最大3枚 + 「その他の○○議案はこちら」。全件は一覧ページへ
6. **前回の定例会** … 地色を `bg-mirai-surface-sunken` に変えて、現在との時間差を色で示す
7. **みらい議会とは / 免責事項**

トップにチャットは置かない。質問は必ず議案から始まる。

## 8. 画面構成 — 議案一覧（会期別）

1. 固定ヘッダー（トップと同一）
2. **会期見出し** … Caprasimo の年ラベル（`SESSION · 2026`）＋和文見出し2段。日程と議案件数。会期の識別を最優先に
3. **絞り込み** … 分野タグの横並び1行のみ。ドロップダウンにはしない。選択中は枠線タグ
4. **議案カード一覧** … 画像なしの詰めた版
5. **準備中の議案** … 破線の枠で件数だけ示す。中身がまだ無いことを、空のカードではなく枠で示す
6. **免責** … 非公式であることを各一覧の末尾に必ず置く

## 9. 画面構成 — 議案詳細

**順序は固定。** 原文より要約を上に置く。

1. 固定ヘッダー … 左は「← 令和8年 第3回定例会」で会期一覧に戻す。公式ページへの導線を必ず1タップ以内に保つ
2. **議決ステータス + 議案番号・種別** … ステータスは色+ラベル。番号と種別は Caprasimo の小さなラベル
3. **表題** … 正式名称をそのまま。Zen Maru Gothic 700
4. **分野タグ**
5. **かんたん要約** … 地色 `bg-mirai-ai-bg`（terracotta-100）、文字 `text-mirai-ai-text`。`AI` ラベルと「AIによる要約です。正確な内容は原文をご確認ください。」を必ず併記し、人が書いた文と視覚的に区別する
6. **議決結果** … 賛否のバー＋会派別の内訳
7. **審議の経過** … 日付＋出来事の縦並び。丸印は terracotta-500
8. **議案の原文** … アコーディオン。**既定では開かない**
9. **区議会の公式ページ（PDF）** … 外部リンク
10. **この議案について質問する** … AIチャットへの導線。sage-200 の1枚。**バナーはフッターの1枚だけ。追尾するボタンは置かない**
11. **免責**

### 議決結果のバー

賛成は `bg-mirai-vote-for`（sage-500）、反対は `bg-mirai-vote-against`（neutral-300）。**反対に赤を使わない。** 反対は異常ではない。`--color-status-rejected` の赤は「議案が否決された」ステータスにのみ使い、賛否の内訳には使わない。会派別の賛否は色だけでなく「賛成／反対」の文字も併記する。

### AI生成部分の扱い

AIが生成した文章はすべて地色を `--color-mirai-ai-bg` にし、`AI` ラベルと注意書きを付ける。一次資料の引用と同じ地色に置かない。議案カードの読める題名と要約もAI生成だが、カードは全体が要約なので地色は分けない——詳細ページで原文と並んで初めて分ける。

## 10. 画面構成 — AIチャット

**チャットは常に1つの議案に紐づく。** 全議案を横断する質問窓は作らない。答えの範囲を画面で示す。

1. 固定ヘッダー … 左は「← 議案第58号」、右は言語セレクタ。会話の途中で言語を切り替えても履歴は保つ
2. **注意書き** … 「この議案の資料をもとにAIが答えます。答えは間違うことがあります。」を冒頭に固定。会話が伸びても最初の1枚は消さない
3. **質問例** … 3つまで。自分の暮らしに引きつけた聞き方で書く（「わが家は対象になりますか？」）。`rounded-full` の枠線
4. **会話** … 自分の発言は `bg-mirai-chat-self`（sage-200）・右寄せ、AIの発言は `bg-card`・左寄せ。角の1つだけを落として向きを示す
5. **出典チップ** … 答えの下に `bg-mirai-source-chip` で示す。**出典が出せない時は答えない**
6. **入力欄** … `rounded-full` の1行＋丸い送信ボタン（44px）
7. **免責** … 「手続きや対象の判断は新宿区の窓口にご確認ください。」で締める。AIを最終的な判断者にしない

## 12. やらないこと

- 直角や1pxの細線で区切る
- パレットをグレーに寄せる（温度がこの案の要）
- Caprasimo 以外の表示体を足す／Caprasimo を日本語に使う
- 行政らしさを出すための青を戻す
- AI生成文を一次資料と同じ見た目にする
- 絵文字をステータスや強調に使う
- 分野タグに色を振る
- 影を4段以上作る
