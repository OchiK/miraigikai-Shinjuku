## 5. PDFリンクの検証方法

URLは推測せず、提出議案ページの `<a href>` を抽出して取得した。
取得した27ファイル（全文23 + 概要4）すべてについて以下を確認した。

1. HTTP 200 かつ `Content-Type: application/pdf`
2. 先頭が `%PDF-` であること
3. 1ページ目のテキストを抽出し、リンク文言どおりの案件（例: 「第５３号議案 新宿区空き缶等の…」）であること

コンテンツIDは9桁ゼロ埋め（例: `000457641`）である。数値として扱うと先頭のゼロが落ちて実在しないURLになるため、seed では文字列として保持し、テストで桁数を検証している。

## 7. 安定識別子

件名だけでは一意に定まらない。**承認第2号と承認第3号は件名がいずれも「専決処分の承認について」で完全に一致する。**
そのため、西暦・会期・案件種別・番号を含む識別子を `bills.slug`（既存のユニークインデックスあり）に格納する。

```text
shinjuku-2026-r2-gian-42     ← 第42号議案
shinjuku-2026-r2-shonin-2    ← 承認第2号
shinjuku-2026-r2-shonin-3    ← 承認第3号
```

seed 内の関連付け（bill_contents / bills_tags / faction_stances / interview_configs）は
すべてこの識別子で突合するよう変更した。訂正前は以下の問題があった。

| 箇所 | 訂正前 | 問題 |
| --- | --- | --- |
| `createBillContents` | 件名で `find` | 承認案件2件を区別できず、先に見つかった方へ誤結合する |
| `createBillsTags` | 件名をキーにした map | 同上 |
| `createFactionStances` | `insertedBills[index]` | 配列順に依存。議案が18件増えた時点で無関係な議案へ割り当たる |
| `createInterviewConfig` | `insertedBills[0]` | 第53号議案向けの `knowledge_source` が別議案に紐づく |

## 11. 残課題

### 11-1. `bills_bill_number_unique` が会期をまたいだグローバル制約（Phase 5 のブロッカー）

`supabase/migrations/20260316000002_add_bill_number_unique.sql` は
`bill_number` に対して会期を含まない部分ユニークインデックスを張っている。

```sql
CREATE UNIQUE INDEX bills_bill_number_unique ON bills (bill_number) WHERE bill_number != '';
```

令和8年第2回定例会の23件は番号がすべて異なるため Phase 1 では問題にならないが、
**第3回定例会を投入する時点で必ず衝突する**（議案番号は会期ごとに振り直され、`承認第N号` は毎年繰り返される）。
本来は `(council_session_id, bill_number)` の複合ユニークにすべきだが、
本PRのスコープ（Phase 1）を超えるため変更していない。Phase 5 着手前に対応が必要。

### 11-2. 未取得のメタデータ

以下は今回の一次情報に記載がないため、推測で補完していない。

- 委員会付託先（`committee_id` は全件 NULL）
- 会派ごとの賛否（`faction_stances` は既存5件のデモデータのみ。実際の会派見解ではない）
- 議案ごとの個別議決日（会期末日 2026-06-19 のみ判明）

### 11-3. タグ未設定

`bills_tags` は分類を確認済みの5件のみに付与している。残り18件は意図的に未分類。
タグは公式メタデータではなく編集上の分類であるため、推測で付与していない。

### 11-4. 第61号議案の表記ゆれ

全文PDF本文は「江戸川橋通り第**Ⅰ**期」（ローマ数字）だが、
提出議案一覧ページと議決結果ページはいずれも「第**1**期」（アラビア数字）である。
公式ページ表記を採用した。
