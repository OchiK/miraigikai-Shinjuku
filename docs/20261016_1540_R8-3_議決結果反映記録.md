## 3. 計画からの訂正・判断

計画の事実との食い違いは、実装時の確認で次の点があった（詳細は PR 本文の「計画からの変更」）。

1. **諮問の「決定」の `status` は裁定が残っている。** 計画の既定案（`reported` / 「本会議で決定」）を暫定で入れた。`packages/shared/src/bills/decision-label.ts` に「決定」の辞書が無く、`reported` のラベルは「専決処分報告」にフォールバックする。ただし coming_soon は、一覧カードにステータスのラベルを出さず（`status` は絞り込みにだけ使う）、詳細ページは `published` のみ表示するため、現状の公開画面には出ない。一方、管理画面のカードと表は `getBillStatusLabel` を使うため、取り込み後は「専決処分報告」と表示される（Codex レビュー指摘）。enum の追加・辞書への追加・別の値のどれにするかは、本番へ反映する前にユーザーが決める。
2. 議決日は議決結果ページに無いので、本文・台帳には書いていない（会議録が出てから別PR）。
3. 依頼文の `passed` は enum に存在しない。既存の変換どおり `approved` + 「本会議で原案可決」。

4. 決算4件のやさしい版・ふつう版の導入部（審議状況の節の外）に「議会が 認めるか どうかを 決めます」「認定するかどうかを議決します」が残る。手続きの説明としては誤りでないが、結果の文と並ぶと現在形が不自然に読める。計画の基準6（審議状況の節以外は変えない）に従って触っていない。直す場合は台帳の再生成が要るので、別途ユーザーが裁定する。
5. 「議決日と会派ごとの賛否は議決結果ページに載っていない」の needs_source 行（66行）は、既存の「出典に記載がない事項」の慣例どおり各案件の全文PDFを出典欄に持つ。主張の対象は議決結果ページなので、出典欄を議決結果ページにするほうが正確だが、判定（needs_source）には影響しない。
