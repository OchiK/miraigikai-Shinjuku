## 3. 実装計画との差異

実装計画（Antigravity 作成）の「主な内容・改正対象」欄は、一次資料と食い違う箇所が多かった。計画ではなく一次資料を採用した。計画の議案番号・件名・全文PDFのID・全10件の原案可決・採決日（3月24日）は一次資料と一致した。

1. **第10号。** 計画は「押印見直し・電磁的記録・手続の明確化」。全文PDFは、聴聞・弁明の機会の付与に係る通知について、門前掲示場への掲示による公示に加えて電磁的記録による公示の方法を定める改正で、押印の見直しは書かれていない。施行日は令和8年5月21日。
2. **第11号。** 計画は「定数見直し・組織体制整備」。実際は定数の表の4つの数字（区長の事務部局 2,538→2,549人、教育委員会の事務部局 141→142人、教育委員会所管の学校 93→89人、合計 2,806→2,814人）の改め。組織体制の整備は書かれていない。
3. **第12号。** 計画は「支給対象・手当額等の改定」。実際は、特定危険現場業務手当の対象組織に都市計画部防災都市づくり課を加えることと、児童相談所の設置方針の変更に伴い児童相談所等現業手当の対象業務を見直すこと（額は「950円」）。
4. **第13号。** 計画は「派遣先団体・派遣職員の処遇等に関する規定整備」。実際は派遣先団体を1件（一般財団法人道路管理センター）加えるだけで、処遇の規定は含まれない。

14. **事実主張だけを台帳に記録。** 「わからない こと」「分からないこと」「資料から読み取れない事項」は読者への開示であり、肯定的な事実主張の台帳には含めない。各節の存在と項目数はテストで検証し、一次資料に含まれない対象を示す表現は個別の回帰テストで固定する。821行はすべて supported。
15. **1文40文字の数え方。** アンカーの正式名称は本文として数える。読みを助ける `［ふりがな］（＝言いかえ）` とアンカー記号 `【】` は数えない。この定義は正本テンプレート、`AGENTS.md`、検証テストで一致させた。

## 4. 標準テンプレートの適用（見出しの決定）

AGENTS.md の見出し文字列を、括弧書きまで含めてそのまま使った。`docs/20261004_1515_議案解説テンプレート定義.md` は一部を「または」付きで書いているため、どちらを使ったかを残す。

| 難易度 | 使った見出し（順序どおり） |
|---|---|
| easy | `この議案は 何ですか` → `何を 変えますか（何を 足しますか）` → `いつから 始まりますか` → `この議案は どうなりましたか` → `わからない こと` |
| normal | `どういう仕組みの話か` → `何が変わるのか（主な変更点）` → `いつから始まるのか` → `この議案のゆくえ` → `分からないこと` |
| hard | `1. 議案の基本情報` → `2. 改め文・条文の内容` → `3. 概要資料が示す改正の位置づけ` → `4. 施行期日と経過措置` → `5. 資料から読み取れない事項` → `6. 一次資料一覧` |

- hard の固定見出しに議決の節がないため、議決（結果・本会議日・委員会審査報告・採決方法・会派別の賛否）は「1. 議案の基本情報」の項目に入れた。第17号は同じ節に少数意見の報告の要旨を置いた。
- 少数意見は「〜と述べた」と客観的に書き、評価語は持ち込んでいない。「620数人」は発言者が「とのことです」と述べた数であり、区の資料にはないため、hard にだけ発言として書いた。
- 見出し構成は `bill-contents-revision.test.ts` が30変種すべてで固定している。
