## 3. 書きかたの方針

- `prompts/easy_ja.md` の絶対条件に従い、政策への賛否を示さず、会派・議員を評価しない。
- 賛否の理由は、会議録の発言者の名前と会派を示して、その人の発言として書く。会派は議会公式の「会派構成」で確認した（採決時の会派名。さわいめぐみ議員は令和8年8月7日に「いのちの党 新宿」へ名称変更する前の「れいわ新選組 新宿」）。
- 第7・8号で反対した会派のうち、理由を討論で述べたのは渡辺やすし委員（現役世代に優しい新宿・減税の会）だけだった。ほかの会派の反対理由は推測せず、「討論では述べられていない」と書いた。質疑で示された懸念（山口かおる委員・おやまだ静香委員）は質疑として書き、反対の理由とは書いていない。
- 会派ごとの賛否は議決結果の欄（#68・#71）に出るため、本文では繰り返さない。

## 4. 検証

1. **引用の照合**: 台帳の主張102件の引用すべてを、出典本文（会議録 body からタグを除いたもの、PDF の `pdftotext` と `pdftotext -layout` と pdfplumber の表セル、XML・HTML の本文）に対し、空白を除いて照合した。「…」で区切った各断片がそのまま出典にあることを確認した（`docs/verification/tools/build_giin_ledger.py`、照合に失敗すると台帳を書き出さない）。
2. **本文と台帳の対応**: 本文に出てくる URL はすべて台帳の出典になっていることを、生成時とテスト（`bill-contents-revision.test.ts`）の両方で確かめる。
3. **内容ハッシュ**: 12変種の `reviewed_content_sha256` を台帳に記録し、81変種の固定テストに加えた。
4. **やさしい日本語**: `easy-japanese-validation.test.ts`（40字、アンカー、西暦と曜日、主要な数値）を通過。`yasashii-nihongo-admin` の `audit.py` も実行した。
5. **事実確認（全文の読み合わせ）**: 12変種の全文を一文ずつ一次資料と突き合わせ、誤り・誇張・帰属・中立性を点検した。別のエージェントによる独立した点検は、利用上限に達して途中で止まったため実施できていない。読み合わせで直した点:
   - 第10号 easy: 与党税制改正大綱の固定資産税を「見直す方向」と書いていた → 大綱の文言（必要な措置を検討し、令和9年度以降の税制改正で結論を得る）に合わせた
   - 第10号 easy: 要約の「税を減らす」は解釈だった → 「財源を 国が 一方的に 取るような 税の 変更」に。題も公式の件名に戻した
   - 第10号 easy: 「何回も」変えてきた（出典に回数の記載なし）を削った
   - 第9号 easy: 「全員」反対なし → 「反対の 声は なく」（会議録は「異議なし」）。「母乳が 大切」→ 出典どおり感染症等のリスクを減らすため
   - 第7号 easy: 渡辺委員の発言を「頼っては いけない」と強めていた → 「頼らない ほうが いい」「事業を 見直して お金を 作るべき」に
   - 第7号 easy: 「いまは 保護者が 払って います」→「保護者が 払う 学用品も あります」（出典は「必要な部分については保護者負担」）
   - 第7・8号 easy: 「意見を 言ったのは」を討論に限定。第8号は「同様の提案」なので「同じような 案」に
   - audit.py の指摘のうち、年度の差を「去年度」と書いていた点と、第1回定例会でも提案した事実の欠落を直した（日付の併記形式に対する DATE-ADDED／DATE-MISSING は誤検知）
6. **台帳の生成手順**: `docs/verification/tools/build_giin_ledger.py`。引用の照合に1件でも失敗すると台帳を書き出さない。
7. **台帳の粒度**: 主張は議案ごとに持ち、easy / normal / hard の3変種に同じ主張の集合を付けている。easy は normal の言い換えで主張の一部だけを使うため、変種ごとに「どの主張を本文で使ったか」までは区別していない。内容ハッシュは変種ごとに固定している。

## 5. 公開の扱い

区長提出議案23件は公開レビューを経ている。この4件の解説は出典突合を終えているが、公開レビューは行っていない。そのため公開はするが `is_review_completed = false` とし、詳細ページにレビュー中の案内を出す（`ShinjukuSessionItem.reviewCompleted`）。

レビューを終えたら、インベントリ（`shinjuku-r8-2-inventory.ts`）の `reviewCompleted: false` を外して本番インポーターを流す。管理画面で `is_review_completed` を切り替えても、次の `import:production` がインベントリの値で上書きするため戻ってしまう。
