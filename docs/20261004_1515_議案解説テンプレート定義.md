# 議案解説テンプレート定義（全会期共通標準）

> 作成日: 2026-10-04  
> 適用範囲: 全会期（R8-1, R8-2, R8-3 および今後のすべての定例会・臨時会）  
> 目的: 会期ごとの構成ブレや情報粒度のばらつきを防ぎ、統一されたUI/UX・透明性・検証可能性を恒久的に担保する。  

---

## 1. 基本原則

1. **正本テンプレートの継承（R8-2モデル）**
   - 議案解説（やさしい／ふつう／くわしく）の構成は、**令和8年第2回定例会（R8-2）**で確立されたスタイルを全会期の正本テンプレートとする。
   - 新規会期の議案を作成する際、独自のセクション構成や自己流の見出しを勝手に導入してはならない。
2. **一次資料の厳格遵守と「わからないこと」の明示**
   - 記載内容は公式の一次資料（議案全文PDF、概要PDF、審議結果PDF、公式会議録）に書かれている事実のみに限定する。
   - 資料から読み取れない事項（施行規則に委任された細目、具体的な手続き変更、財政効果の試算など）は、AIによる推測や補完を固く禁じ、必ず**「わからないこと / 資料から読み取れない事項」**セクションを設けて明示する。
3. **主張台帳（Claim Ledger）との完全同期**
   - すべての事実主張は主張台帳（UTF-8 BOM付きCSV）に記録し、一次資料との突合（status: supported）および本文sha256の機械的検証（`bill-contents-revision.test.ts`）を通過させる。

## 2. 条例案・議決案件の標準テンプレート

### 🟢 やさしい（easy）
- **文字数・文体**: 1文40文字以内（句点 `。` で区切る）。文字数はアンカーの `【正式名称】` を本文として数え、読みを助ける注記 `［ふりがな］（＝言いかえ）` とアンカー記号 `【】` は数えない。行政用語は初出時に `【正式名称】［ふりがな］（＝言いかえ）`、2回目以降は `【正式名称】` とする（アンカー保持プロトコル）。元号と西暦を併記（例: `2026年（令和8年）3月24日`）。
- **見出し構成**:
  1. `## この議案は 何ですか`
     - 制度の前提、対象となる条例名、これまでの決まりを平易に説明。
  2. `## 何を 変えますか`（または `## 何を 足しますか`）
     - 今回新しく決めること、変更点、対象の限定条件（法律による除外等）を箇条書きで平易に説明。
  3. `## いつから 始まりますか`
     - 施行期日（公布の日から○年○月以内、規則で定める日等）。
  4. `## この議案は どうなりましたか`
     - 【原案可決】等の議決結果、決まった定例会名、会期日程。
  5. `## わからない こと`
     - 具体的な対象範囲や運用方法など、今回の資料からは確認できない事項を読者に開示。

### 🟡 ふつう（normal）
- **文体**: です・ます調の読みやすい標準的な解説文。
- **見出し構成**:
  1. `## どういう仕組みの話か`
     - 背景、法体系や上位法との関係、条例の位置づけ。区の概要資料の公式説明文を引用ブロックで提示。
  2. `## 何が変わるのか`（または `## 主な変更点` / `## 何が追加されるのか`）
     - 条例改正の具体的なポイント。重要な条件・限定・規則委任を整理。
  3. `## いつから始まるのか`
     - 施行期日、公布日からの期間、経過措置の有無。
  4. `## この議案のゆくえ`
     - 審議結果（原案可決／否決）、提出会期および会期期間。
  5. `## 分からないこと`
     - 一次資料に書かれていない実務上の詳細、今後の規則委任事項を明記。

### 🔴 くわしく（hard）
- **文体**: である調の精密な法規・政策解説。
- **見出し構成**:
  1. `## 1. 議案の基本情報`
     - 提出日、提出者（新宿区長）、対象条例名、議案本文に付された公式提案理由の引用。
  2. `## 2. 改め文の内容`（新規制定の場合は `## 2. 条例の骨子`）
     - 改め文の該当箇所引用、新旧対照、条文上の限定条件や委任関係の整理テーブル。
  3. `## 3. 概要資料が示す改正の位置づけ`
     - 提出案件概要（条例関係）の記載内容と趣旨。
  4. `## 4. 施行期日と経過措置`
     - 附則に定められた施行期日、経過措置規定。
  5. `## 5. 資料から読み取れない事項`
     - 資料の限界と実務的論点の開示。
  6. `## 6. 一次資料一覧`
     - 全文PDF、概要PDF、URL、sha256ハッシュ一覧表。

## 3. 予算議案の標準テンプレート

### 🟢 やさしい（easy）
- 見出し: `## この議案は 何ですか`、`## 何に お金を 使いますか`、`## お金は どこから きますか`、`## この議案は どうなりましたか`
- 金額表記: 漢字表記（例: `約287億円`、`1億400万円`）

### 🟡 ふつう（normal）
- 見出し: 予算の総額・規模、`## 何にお金を使うのか`（主要事業別小見出し）、`## どこからお金を出すのか`（歳入内訳テーブル）、`## この議案のゆくえ`

### 🔴 くわしく（hard）
- 見出し: `## 1. 補正（当初予算）の構成`、`## 2. 第1表 歳入歳出予算`（歳出・歳入の款別内訳テーブル）、`## 3. 財源構成と主要事業`、`## 4. 審議結果と会派態度`、`## 5. 一次資料一覧`

## 4. 議員提出議案（発言・討論を含む場合）の追加ルール

議員提出議案（特に賛否が分かれた条例案・意見書等）において、本会議や常任委員会の発言を盛り込む場合は以下を必須とする：
- `easy`: 賛成した議員・会派、反対した会派の態度を平易に記述。
- `normal`: `## 賛否の討論`（または `## 審議の経過`）見出しを設け、少数意見留保報告や討論の要旨を記載。
- `hard`: `## 討論と議決` セクションにて発言者・所属会派・会議録ID・発言要旨（金額や政策根拠）を記述し、一次資料一覧に会議録リンクを明記。
- **中立性の堅持**: 発言内容は「〜と述べた」と客観的に記述し、賛否の優劣を評価する言葉は一切使わない。反対会派に討論がない場合は「反対した会派からの本会議討論はありませんでした」と事実のみを記載する。
