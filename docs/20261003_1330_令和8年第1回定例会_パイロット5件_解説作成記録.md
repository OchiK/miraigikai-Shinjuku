## 3. 成果物

- `packages/seed/main/bill-contents-r8-1-data.ts`: 15変種
- `docs/verification/20261003_1330_claim-ledger-r8-1-pilot.csv`: 主張台帳（UTF-8 BOM、CRLF）481行。supported 466行、needs_source 15行（各変種の「出典に記載がない事項」）
- `docs/verification/tools/r8_1/`: 一次資料の取得、台帳の仕様（`spec.py`）、台帳の生成（`ledger_build.py`）、本文の書き出し（`dump.ts`）、再生成（`rebuild.sh`）

台帳の `evidence_excerpt` は、生成時に一次資料の抽出テキスト（NFKC 正規化・空白除去）と機械照合している。「…」で区切った断片のすべてが出典に含まれなければ生成が失敗する。`reviewed_content_sha256` は本文の `title\nsummary\ncontent` から計算した値で、`bill-contents-revision.test.ts` が本文との一致を検証する。

機械照合が確かめるのは「引用が出典に実在すること」で、「主張が引用の内容と合っていること」は人が確かめる必要がある。2026-10-03 の独立レビューで全471行を確認したところ、複数の表・条文・事実を一つの行にまとめ、一部の引用だけでは主張全体を支えられない行が見つかった。該当する主張を根拠ごとの原子的な行へ分割し、採決日と可決結果も別々の会議録行に対応付けた。修正後の481行について、引用の機械照合と主張・引用の意味対応を再確認した。

計画の前提「5件とも2026年3月24日の本会議で可決」は第5号議案には当たらない。第5号議案は先議で、会期の初日に可決されている。第5号議案の本文は「2026年（令和8年）2月17日の 本会議で 決まりました」（easy）、「令和8年2月17日の本会議で原案可決」（normal）と書いた。ほかの4件は計画のとおり3月24日と書いた。

議員提出議案第6号は、会議録が「原案のとおり可決」と記すので、easy の見出し語は「原案可決」にした（議案の概要と審議結果の表記は「可決」）。

`bill-contents-revision.test.ts` が、本文の採決日（第5号議案だけ2月17日）と、台帳の審議状況の行が引く会議録の日（schedule 2 または 5）を、議案ごとに固定している。

### 5.2.1 掲載日時（`bills.published_at`）

R8-1 の `published_at` は、これまで全件 null だった（インベントリの注記は「解説を公開する Phase 2 で決める」とする）。公開一覧は `published_at` の降順で並べ、PostgreSQL は降順で null を先頭に置くため、null のままだと公開した5件が R8-2 の議案より前に並ぶ。R8-2 と同じ方針で、解説を公開した5件に会期末日（2026-03-24）を入れ、残る43件は null のままにした。この値は議決日ではなく掲載時点である。`shinjuku-r8-1-inventory.ts` の `R8_1_PUBLISHED_AT` と、同テストで固定している。

### 5.3 easy の書式

実装計画の「`【行政用語（言い換え）】`」は、リポジトリの規約（アンカー保持プロトコル `【正式名称】［ふりがな］（＝やさしい言いかえ）`）と書式が違う。テスト（`easy-japanese-validation.test.ts`）が検証するのは後者なので、後者に従った。

### 5.4 各案件の注意

- 第1号: 議案は款・項ごとの金額までで、個々の事業の説明はない。解説は全文だけを根拠とする（概要PDFは提出議案一覧ページにない）。賛否は議案の概要と審議結果から、共産・れいわの反対を書いた。
- 第5号: 追加給付の対象者・金額、単価改定の金額は出典にない。
- 第20号: 利用料の金額は第21号議案（別の議案）の領域で、この条例の本文にはない。
- 第31号: 地域共生施設の内容と届出の細目は規則で定める。
- 意見書: 3,600件、1,100件、76%、92% などは意見書自身の記述として書き、区の調査結果とは書いていない。「昨年12月」は意見書の記載どおりで、年は補っていない。意見書を提出した議員の氏名は出典にない。
