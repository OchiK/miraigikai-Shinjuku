# 会派賛否データ投入計画（令和8年第2回定例会）

Phase 7-C（#66）で、議案詳細の会派名から議員一覧へ移るリンクを実装した。ただし `faction_stances` が空のため、今はどの議案にも表示されない。この文書は、会派ごとの賛否を一次情報から投入する手順を決めるためのもの。

## 1. 結論

- 出典は **新宿区議会だより**。各定例会号の2面に「議案の概要と審議結果（賛成…○、反対…×）」の表があり、議案ごとに会派別の賛否が載っている。
- 当サイトの議案23件はすべて令和8年第2回定例会のもので、**No.322（令和8年7月25日発行）の1号で全件を賄える**。
- 表は pdfplumber できれいに抽出できる（付録A）。23件中19件は全会一致で、全会一致でないのは4件だけ。
- 投入前に決めることが2つある（§4、§5）。**採決時の会派名をどう出すか**と、**出典をどこに表示するか**。

## 3. 会派の対応ルール

区議会だよりの列は **採決時点の8会派**。DBの `factions` は **令和8年8月7日時点の9会派**で、その間に2つの変化がある。

| 区議会だより | DB `factions.name` | 備考 |
|---|---|---|
| 自参ク | `jimin-sansei` | `alternative_names` に「自参ク」あり |
| 公明 | `komei` | 同「公明」 |
| 共産 | `kyosan` | 同「共産」 |
| 新宿会 | `shinjuku-mirai` | 同「新宿会」 |
| 民無ク | `rikken` | 同「民無ク」 |
| 維新 | `ishin` | 同「維新」 |
| 現役 | `genekisedai` | 同「現役」 |
| れいわ | `inochi` | 令和8年8月7日付けで「れいわ新選組 新宿」から「いのちの党 新宿」に名称変更（seed の data.ts に記録済み）。`alternative_names` に「れいわ新選組 新宿」あり。所属はさわい めぐみ議員1名 |
| （列なし） | `update` | 「アップデート新宿」は定例会の後に結成された（No.322「会派の異動」。大門さちえ議員が自民・参政クラブから移籍）。採決時には存在しないため、**賛否の行を作らない** |

ルール:

1. 列の見出しは、`factions.alternative_names` の完全一致で DB の会派に対応させる。一致しない見出しが出たら投入を止め、人が確認する。
2. 記号は ○→`for`、×→`against` だけを変換する。それ以外（空欄、「−」、退席の注記など）が出たら推測で埋めず、投入を止める。
3. 賛否は **会派の態度** として扱う。所属議員が個別に違う投票をしても、この資料からはわからない。画面の文言も「会派の賛否」のままにする。
4. 採決時に存在しなかった会派（`update`）の行は作らない。そのため、議決結果のバーは8会派の集計になる。

## 4. 決めること①：採決時の会派名

いのちの党の賛否を出すとき、採決時の名前は「れいわ新選組 新宿」だった。今の `FactionStanceCard` は `factions.display_name`（現在の名前）を表示するため、6月の採決に8月以降の名前が付く。

| 案 | 内容 | 手間 |
|---|---|---|
| A | そのまま現在の名前を出す | なし。ただし史実と表記がずれる |
| B（推奨） | `faction_stances` に `faction_name_at_vote text null` を追加する。現在名と違うときは「いのちの党 新宿（採決時：れいわ新選組 新宿）」のように併記する | マイグレーション1本、表示の小改修、テスト |

B を推奨する。会派の再編は今後も起きる（今回だけで2件あった）。一次資料どおりの名前を残しておけば、出典と画面の表記が合う。

## 5. 決めること②：出典の表示

AGENTS.md は「出典が出せない答えは返さない」ことを求めている。今の議決結果カードには出典の表示がない。

| 案 | 内容 |
|---|---|
| A（推奨） | 会期ごとの定数（例: `FACTION_STANCE_SOURCES["r8-2"] = { label: "新宿区議会だより No.322（令和8年7月25日）", url }`）を置き、カードの下に「出典：…」を出す。スキーマ変更なし |
| B | `faction_stances` に `source_url` 列を追加する。行ごとに持てるが、同じ値を184行に繰り返すことになる |

区議会だよりは会期ごとに1号なので、A で足りる。

## 6. 投入手順

1. **seed を作る。** `packages/seed/main/shinjuku-faction-stances.ts` に、議案の slug（`gianKey`）×会派 slug→賛否 の表を書く。data.ts の `factionStancesBySlug` にある「会派見解を投入しない」という注記を差し替える。
2. **件数を固定するテストを書く。** 23議案×8会派＝184行。`against` は4行で、内訳は第42号（現役）、第45号（れいわ）、第49号（れいわ）、第54号（共産）。`update` の行は0件にする。
3. **PDFと照合するスクリプトを作る。** 区議会だよりのPDFを pdfplumber で読み、seed と1行ずつ比べて差分を出す（Python。CIには載せず、seed を変えたときに手で実行する。`verify:council-questions` と同じ扱い）。議案名は表の先頭から照合する。「専決処分の承認について」は2件あるので、「（第2号）」「（第３号）」で区別する。
4. **人が目で確認する。** PDFの2面を開き、全会一致でない4件の×の位置を目で確かめる。抽出が正しくても、列ずれは件数テストでは見つからない。
5. **本番インポーターを広げる。** 今の `packages/seed/production` は `faction_stances` を扱わない。7-A・7-B と同じく、キーを「議案 slug＋会派 slug」にして差分を出す（dry-run → `import:production`）。マイグレーションはマージ時に本番へ自動適用される。
6. **本番に投入する。** Ken が dry-run の差分を確認してから `import:production` を実行し、`bills` のキャッシュを再検証する。

§4 で B を選んだ場合は、1〜5 に `faction_name_at_vote` を含める（いのちの党の23行に「れいわ新選組 新宿」を入れる）。

## 9. 質問と議案の紐づけについて（別件）

§7 の3件の討論は、特定の議案に対する実在の発言で、議案ページに「この議案についての討論」として出せる。ただし次の点から、賛否の投入とは別に扱う。

- 件数が少ない（3件とも同じ議員）。
- `council_member_questions` は「質問」の表で、`question_kind` は代表質問・一般質問しかない。討論を載せるには種別（例: `debate`）と賛否の向き、画面の文言を追加する必要がある。
- 委員会の質疑のほうが議案ごとの発言は多いと見込まれる。ただし委員会の会議録が同じ API で取れるかは、まだ確認していない。
