## 1. 目的とスコープ

PR #54 において、ヘッダー、トップページ、議案カード、フッター、議案詳細のステータスバッジ・免責の多言語化（`locale === "en"`）が実装された。
本タスクでは、BACKLOG P8-12 および ROADMAP に明記された残作業をすべて完了させ、サイト全体の UI 多言語化（Chrome i18n / フル英語モード対応）を完成させる。

## 2. アーキテクチャと設計方針

### 2.1 型安全なメッセージ管理（`UiMessages`）
- すべての UI 文字列は `web/src/features/i18n/shared/ui-messages.ts` の `UI_MESSAGES` に集約する。コンポーネント内への英語文字列の直書きは禁止。
- 引数を取る動的文言（件数、会期名、議員名など）は関数として定義し、単数形・複数形（例: `1 question` vs `2 questions`）を正しくハンドリングする。
- 議案名・議員名・会派名などの一次データ（DB由来の日本語）を埋め込む際は、HTML の `lang="ja"` 属性を付与してスクリーンリーダーやフォントレンダリングに配慮する。

### 2.2 RootLayout の `<html lang>` 対応
- Next.js App Router では RootLayout は Server Component であり、`async` 関数として定義可能。
- `const locale = await getLocale();` を実行し、`<html lang={locale}>` を出力する。
- 既存のクライアントサイド・サーバーサイドのハイドレーションやフォント読み込みに影響を与えない。

### 2.3 ページコンポーネントへの `locale` の伝搬
- `sessions/[slug]/bills/page.tsx`, `councilors/page.tsx`, `councilors/[id]/page.tsx`, `bills/[id]/page.tsx` において、`await getLocale()` で `locale` を取得し、配下の Feature コンポーネントへ Props として渡す。
- Client Components は Props として `locale` を受け取る（コンポーネントのテスト容易性を担保）。

## 5. 実装時の変更点（2026-09-26、コードとの照合後）

1. **`<html lang>` は `ja` のままにした。** §1-1・§2.2 は実施しない。一覧カードの議案名・タグ、FAQ・規約・インタビュー・チャットなど、日本語のまま出す文字列の多くは `lang="ja"` を付けずにルートの `ja` に頼っている。ルートを `en` にするとそれらが英語として扱われる（WCAG 3.1.1 / 3.1.2）。PR #54 と同じく、英語にした部分に `lang={locale}` を付け、その中の DB の日本語に `lang="ja"` を付ける。
2. **DB の日本語を差し込む文言は `{ before, after }`（`AroundJa`）で持つ。** §3 の `(sessionName: string) => string` 型では、差し込んだ日本語に `lang="ja"` を付けられないため。関数の引数は数値だけにした。
3. **出典の定数（基準日・掲載範囲）の英語**は `councilors/shared/constants.ts` の `en` に置いた。日本語の定数をそのまま英語の文に差し込むと日本語が混ざるため。
4. **対象を実際のコンポーネントに合わせた。** `CouncilorSources`・`ExternalSourceLink`・共有モーダルを追加した。審議の経過はステップ名・日付ラベル・議決用語まで英語にした。共有にリンクのコピー・トーストは無く、実際は「記事を共有する」「問題を報告する」と共有モーダル。かんたん要約に難易度表示は無い。
5. **議員の質問カードは日本語のまま**（議案詳細と同じ扱い）とし、英語表示では案内を添える。議員詳細の傾向の1文は英語表示では出さない。
6. 定例会の議案一覧の絞り込みボタンに `aria-pressed` と `role="group"` の名前を付けた。
