# やさしい日本語 再設計方針

作成日: 2026-09-18

## 何を変えたか

やさしい日本語（`difficulty = easy`）の位置づけを、「日本語学習者向けの易読化」から「**外国人住民が議案の内容と自分への影響を正しくつかむための行政情報**」に変えた。あわせて、生成プロンプト・AIチャット・パイロット3議案の本文・自動テストを新しい基準に揃えた。

## なぜ変えたか

これまでの easy 版は「1文40字以内」「難しい言葉を使わない」を中心に組み立てていた。読みやすさは上がるが、行政文書としては次の問題があった。

| 観点 | これまで | 問題 |
|---|---|---|
| 行政用語 | `あとから 足す お金（補正予算）` のように平易語を主にして正式名称を括弧に落とす | 読み手が区の広報・議事録・窓口の案内と照合できない。検索もできない |
| 日付 | `令和8年6月10日` を そのまま残す | 元号のカレンダーを持たない住民が、いつのことか判断できない |
| 情報量 | 読みやすさのために短くなりがち | 条件・例外・対象者の範囲が落ちると、制度を誤解する |
| モダリティ | 「〜します」「〜できます」に均されやすい | 義務と任意の区別が消える |

`/yasashii-nihongo-admin`（行政文書のやさしい日本語）の基準を採り、優先順位を「読みやすさ < 正確さ」に置き直した。

## 適用した基準

### アンカー保持プロトコル

公式用語の初出を `【正式名称】［ふりがな］（＝やさしい言いかえ）` で書き、2回目以降は `【正式名称】` だけにする。正式名称を**軸（アンカー）**として本文に残し続けることで、読み手は窓口の看板・申請書の見出し・区の広報と同じ語で照合できる。

パイロット3議案でアンカーにした用語:

| 議案 | 用語 |
|---|---|
| 第42号 | 補正予算、応援券、共通券、繰入金、諸収入、特別区債、財政調整基金、社会資本等整備基金、原案可決 |
| 第43号 | 補正予算、都支出金、寄附金、繰入金、諸収入、財政調整基金、原案可決 |
| 第44号 | 条例、新宿区基本構想、答申、公布の日、原案可決 |

### 日付の西暦換算

読み手が日付として読む箇所は、西暦に直して曜日を添える。初出は `2026年（令和8年）6月10日（水）` のように元号を併記し、2回目以降は西暦だけでよい。年度も同じ（`2026年度（令和8年度）`）。

**法令番号・条例番号は対象外**とした。`平成19年 新宿区条例 第61号`、`昭和43年法律第100号` は日付ではなく識別子であり、西暦に直すと公式の表記と一致しなくなる。この例外は `easy-japanese-validation.test.ts` の元号検査に実装し、検査そのものの回帰テスト（裸の元号と法令番号を見分けられること）も置いた。元号の残存は出現位置ごとに判定する。本文のどこか1か所が併記になっていれば通る、という抜けを作らないためである。

換算した日付（曜日は暦から確定したもの）:

| 原文 | 書き換え後 |
|---|---|
| 令和8年6月10日（提出日・会期初日） | 2026年（令和8年）6月10日（水） |
| 6月19日（会期末日） | 6月19日（金） |
| 7月1日〜7月27日（商品券の申し込み） | 2026年7月1日（水）〜7月27日（月） |
| 9月16日〜10月16日（販売） | 2026年9月16日（水）〜10月16日（金） |
| 10月1日〜1月8日（利用） | 2026年10月1日（木）〜2027年1月8日（金） |
| 令和8年8月〜12月（仮園舎の改修） | 2026年（令和8年）8月から 12月 |
| 令和9年1月（移転予定） | 2027年（令和9年）1月 |
| 令和8年度末（基金残高） | 2026年度（令和8年度）の 終わり |
| 令和9年度／令和10年度（債務負担行為） | 2027年度（令和9年度）／2028年度 |

### モダリティの保持

義務・禁止・任意・推奨を崩さない。第44号議案では、条文「議会の議決を経なければならない」に対応する説明を「区議会が 決めます」から「**区議会が 決めなければ いけません**」に直した。

### 情報量

条件・例外・金額・対象者の範囲を落とさない。今回の改訂では事実の増減をしていないことを、新旧本文の数値トークンの多重集合比較と正規化テキスト差分で確認した（差分は表記の変更のみ）。

## 40字ルールとの整合

デザインシステム定義 §3 の「easy: 1文40字以内、行間2.0、漢字にルビ、分かち書きあり」は維持する。

ただしアンカーの `［ふりがな］（＝言いかえ）` をそのまま文字数に数えると、アンカーを付けるほど40字を超える。これでは規約が「公式名称を消せ」という圧力に変わってしまう。そこで**文長の検査ではアンカーを正式名称に畳んでから数える**ことにした。

畳む処理は `packages/seed/main/easy-japanese-text.ts` の `stripAnchorGloss` に純粋関数として置き、`splitIntoSentences` の途中に挟んでいる。

```text
今回は【補正予算】［ほせいよさん］（＝あとから 足す お金）です。
→ 今回は補正予算です（9字として数える）
```

## 主張台帳の扱い

本文を変えたので、`bill-contents-revision.test.ts` の内容ハッシュ検査が落ちる。ハッシュだけを書き換えてはならないという規約に従い、次の順で対応した。

1. 新旧本文の数値トークンを比較し、金額・件数・割合・年齢が1つも増減していないことを確認
2. アンカーを畳んだ正規化テキストの差分を取り、変更が表記（アンカー・西暦・曜日）に限られることを確認
3. 日付を含む主張文（`R42-E-03` など14行）を新しい表記に更新
4. `reviewed_content_sha256` を再計算

曜日は一次資料に書かれていないが、資料に書かれた日付から暦で一意に決まる。主張文には「原文の元号表記を西暦と曜日に換算」と明記した。

## 残っていること

- easy 版は第42・43・44号議案の3件のみ。残り20件は未整備で、表示時は normal にフォールバックする。
- 「区民への影響ボックス」はプロンプト側に定義したが、既存3議案の本文には入れていない。窓口名・問い合わせ先が一次資料にないため、推測で埋めないという原則を優先した。住民の行動を伴う議案を今後 easy 化するときに使う。
