## 3. 実装計画との差異

実装計画（Antigravity 作成）の議案番号・件名・全文PDFのID・全10件の原案可決は一次資料と一致した。計画には各議案の「主な内容・改正対象」欄がなく、内容は一次資料から起こした。一方、次の点は一次資料と食い違い、計画ではなく一次資料と AGENTS.md を採用した。

1. **第21号議案の採決日。** 計画は「本会議会議録（2026年3月24日 第4日第4号）」とし、10件とも3月24日に採決されたと読める。3月24日の会議録（schedule 5、188発言）に第21号議案は出てこない。第21号議案は**2月17日**の本会議（schedule 2、第1日第1号）で上程・付託され、同じ日に委員会審査報告書が提出されて追加日程第1として可決された。本文・台帳・テストは第21号議案だけ2月17日にした。ほかの9件は3月24日で一致した。
2. **hard の見出し。** 計画は7節（`5. 審議状況`、`6. 出典に記載がない事項`、`7. 一次資料一覧`）を挙げたが、AGENTS.md の固定見出しは6節（`5. 資料から読み取れない事項`、`6. 一次資料一覧`）で、受入基準も「AGENTS.md の見出しと完全一致」としている。AGENTS.md に従い、議決（結果・本会議日・委員会審査報告・採決方法・会派別の賛否）は「1. 議案の基本情報」の項目に入れた。
3. **easy・normal の第2見出し。** 計画は新規制定（第21・28号）で `主な ルール`／`何を 決めますか`／`主な内容` に変えるとした。AGENTS.md は条例案の見出しを1通りに固定しているため、新規制定を含む10件すべてで `何を 変えますか（何を 足しますか）`、`何が変わるのか（主な変更点）` を使った。
4. **計画の作業手順の `cp .claude/settings.local.json`。** メインのチェックアウトに `.claude/settings.local.json` がなく、コピーに失敗した。`.env` のコピーと `pnpm install --frozen-lockfile` は成功した。
5. **会議録の取得範囲。** 計画は3月24日の会議録だけを前提にしていた。第21号議案のため、取得スクリプトは2月17日の会議録も取り、台帳の出典キーは `M2_<発言ID>`（2月17日）と `M5_<発言ID>`（3月24日）を使い分ける。
6. **曜日。** 資料に曜日の記載がない施行日（2026年4月1日（水）、同5月1日（金）、同10月1日（木）、2027年3月31日（水）など）は、暦から換算した。Group A と同じ扱い。
7. **第28号の基準時の日付。** easy だけ、平成8年5月31日を「1996年5月31日」と西暦で書いた。easy の検査（`bareEraDates`）は、元号の日付が `20xx年（` の直後に置かれたものだけを併記と認めるため、1996年の元号併記が書けない。normal・hard は「平成8年5月31日（基準時）」とした。
8. **条例番号。** 第26号の全文PDFの条例番号欄は「新宿区条例第２号」で、公布前の仮の記載なので、本文には条例番号を書いていない（テストで固定した）。第21〜25号は欄が「新宿区条例第　号」と空欄で、第27〜30号は欄自体がない。

## 4. 議案ごとの注意点（本文で断定を避けたもの）

- **第22号。** 施行日は「法律の附則の規定の施行の日」と「公布の日」の遅い方で、日付を断定していない。改正前の第6条の全文は改め文にないため、組み合わせた後の文を書いていない。
- **第23号。** 「無料」の語は、提出案件概要と審議結果PDFにだけある。全文PDFの改め文は附則第4項の日付を改めるだけなので、本文は無料の出典を概要資料と明記した（台帳もそれらの出典を引く）。
- **第24号・第26号・第27号。** 引用条項・法律名・用語の改正だけで、手数料の額や改正前の条文は改め文に書かれていない。本文は影響を推測せず、わからないことに挙げた。
- **第25号。** 施行日が2段階（第1条は4月1日、第2条と附則第2項は10月1日）で、経過措置は10月1日以後の確認申請等に適用する。提出案件概要の表に載る例は遊技場と銀行その他の金融機関だけで、全文PDFの改め文はスポーツ施設（25→400平方メートル）、学習・教養・趣味等の教授施設、小売店・飲食店の項も改める。台帳の引用は、列が交互に並ぶ表の抽出テキストに合わせて断片に分けた。
- **第28号。** 地区の区域はこの議案の資料にない。罰則（20万円以下の罰金）、両罰規定、既存建築物の緩和（1.2倍）、附則による旧条例の廃止を、easy・normal・hard の全難易度で書いた。
- **第29・30号。** 「ワンルーム形式」の定義、再配達の削減の措置、標識の設置を開始すべき時期は改め文にない。第30号の第2条第1号は全文改めの形で書かれているため、改正前の定義との差分は断定していない。

## 5. 標準テンプレートの適用（見出しの決定）

AGENTS.md の見出し文字列を、括弧書きまで含めてそのまま使った（Group A と同じ）。

| 難易度 | 使った見出し（順序どおり） |
|---|---|
| easy | `この議案は 何ですか` → `何を 変えますか（何を 足しますか）` → `いつから 始まりますか` → `この議案は どうなりましたか` → `わからない こと` |
| normal | `どういう仕組みの話か` → `何が変わるのか（主な変更点）` → `いつから始まるのか` → `この議案のゆくえ` → `分からないこと` |
| hard | `1. 議案の基本情報` → `2. 改め文・条文の内容` → `3. 概要資料が示す改正の位置づけ` → `4. 施行期日と経過措置` → `5. 資料から読み取れない事項` → `6. 一次資料一覧` |

- 見出し構成は `bill-contents-revision.test.ts` が30変種すべてで固定している。
- 「わからないこと」は読者への開示であり、肯定的な事実主張の台帳には含めない。各節の存在と項目数（2件以上）はテストで検証した。
- 10件とも全会派賛成のため、討論の記載はなく、反対会派にも触れていない（テストで「反対」を含まないことを固定した）。
