# 多言語方針の見直し: 英語のみ翻訳し、他言語は案内ページにとどめる

2026-09-24 決定。**計画のみで、実装はまだ行っていない**（BACKLOG の P3-5）。

この文書は、BACKLOG P3-3 に記録した「B+Cハイブリッド方針」（#40）を置き換える。

関連: [20260923_1500_多言語基盤_ロケール方式の決定記録.md](20260923_1500_多言語基盤_ロケール方式の決定記録.md)、[I18N_AND_EASY_JAPANESE.md](I18N_AND_EASY_JAPANESE.md)

## 1. 決定

| 論点 | 決定 |
|---|---|
| 議案の翻訳を公開する言語 | **英語のみ**。運営が内容を確認したうえで `reviewed` にする |
| zh-Hans / ko / ne / my / vi | 議案の翻訳は公開しない。言語ごとに**案内ページを1枚**だけ置く |
| 多言語サイト化 | しない。UI 全体の翻訳（P3-1 の拡張）も行わない |
| 既存の5言語の翻訳下書き | DB に残す。削除はしないが、公開されない仕組みを入れる（§4） |
| 案内ページのネイティブ確認 | しない。代わりに内容を短く、誤訳しても害の小さいものに限る（§3） |
| 用語集 | 作らない |
| AIチャット | 利用者の言語で答えてよい（P4-1 のまま）。AIの回答であることと日本語の出典を必ず示す |
| 対象言語の選び方 | 現行の5言語のまま。新宿区の在留外国人の統計にもとづいて選んだもの |

## 2. 経緯と理由

運営が内容を確認できるのは英語だけで、他の5言語は確認できない。

- 利用者はブラウザの翻訳機能で、日本語のページを自分の言語で読める。
- 確認していない翻訳を載せると、誤りは「このサイトが議案について誤ったことを書いた」ことになる。ブラウザ翻訳の誤りはGoogleなど翻訳機能の側の誤りと受け取られるが、サイトに載せた翻訳の誤りはサイトの責任になる。議案の内容や議決の結果を正しく伝えることは、このサイトの信頼の基盤。
- 「AIによる未検証の翻訳です」と注記しても、日本語が読めない読者には誤りを見分けようがない。注記だけでは読者を守れない。
- 日本語を直すたびに全言語の翻訳が古くなり、確認できない作業が増え続ける。

一方で、翻訳を用意する利点のうち「検索で見つけてもらえる」「外国人住民を想定していると伝わる」の2つは、案内ページで得られる。議案本文は、ブラウザ翻訳とやさしい日本語（全23件で作成済み）で読んでもらう。

### B+C方針（#40）をやめた理由

B+C方針は、5言語の未確認の翻訳を警告付きで公開し、コミュニティのレビュー協力者が現れたら順に `reviewed` にするものだった。レビュー協力者のあてがないまま未確認の翻訳を議案ページに出すことになり、上記の問題がそのまま残るためやめる。協力者が現れた場合に再開できるよう、翻訳データとレビュー画面は残す。

### 検索エンジンにだけ翻訳を見せる案も採らない

翻訳ページをサイトのメニューに出さず、sitemap だけで検索エンジンに登録する案も検討した。検索から来る読者はまさに未確認の翻訳にたどり着く人たちなので、リスクは減らない。内部リンクのないページは検索順位も上がりにくい。

## 3. 案内ページ

### 置く言語

zh-Hans / ko / ne / my / vi の5言語。英語は議案の翻訳を公開するため、案内ページは作らない（トップから英語表示に切り替えられる）。

### 載せる内容

この5つだけにする。議会の仕組みや議案の内容の説明は載せない。

1. このサイトの説明（新宿区議会の議案をわかりやすく説明するサイトであること、運営者、区の公式サイトではないこと）
2. ページは日本語で書かれていて、日本語が正本であること
3. ブラウザの翻訳機能の使い方
   - Chrome・Safari（iPhone）・Android の手順を、スクリーンショット付きで
   - LINE・X などのアプリ内ブラウザでは翻訳が出ないことがあるため、「外部ブラウザで開く」手順も載せる
   - ふりがな（ルビ）を表示していると翻訳が崩れることがあるので、先にふりがなを切ってから翻訳する
4. 難易度を「やさしい」に切り替える方法（やさしい日本語で読める）
5. AIチャットに自分の言語で質問できること（回答はAIによるもので、出典は日本語の資料）

### 書き方

- **やさしい日本語で原文を書き、それを機械翻訳する。** 短く平易な文は、行政の日本語より機械翻訳の精度が高い。
- **翻訳の横に日本語の原文を並べる。** 日本語が少し読める人の助けになり、誤訳に気づいた人が指摘しやすい。
- **スクリーンショットで手順の大半を伝える。** 翻訳文に頼る量を減らす。
- **ページの先頭に1行、機械翻訳であることと連絡先を各言語で書く。** 誤訳に気づいたネイティブ話者から連絡をもらえるようにする。

### URL と検索エンジン

案内ページは検索で見つけてもらうためのものなので、言語ごとに固有の URL を持たせる（例: `/guide/vi`）。議案ページの Cookie 方式（決定記録 §1）とは別扱いにする。

- `web/src/lib/routes.ts` にルート関数を追加する
- 5言語のページを互いに `hreflang` で結び、sitemap に載せる
- ページ全体に `<html lang>` ではなく、本文の要素に各言語の `lang` を付ける（日本語の原文には `lang="ja"`）
- トップページとフッターから、各言語の自言語表記（`LOCALE_NATIVE_NAMES`）でリンクする

## 4. 英語以外の翻訳を公開させない仕組み

現状、公開の条件は「`reviewed` かつ日本語のハッシュが一致」だけで、言語は問わない。管理画面で5言語のどれかを承認すれば、その翻訳は公開される。言語切替のメニューにも7言語すべてが出ている。これを次のように改める。

- `packages/shared/src/i18n/` に公開する言語の一覧（`PUBLIC_TRANSLATION_LOCALES = ["en"]`）を置き、公開の判定でこの一覧にない言語を常に不可にする。テストで固定する。
- 言語切替のメニューは日本語と英語だけにする。`?lang=vi` などで他言語を指定されても日本語で表示する。
- 管理画面の承認操作は、一覧にない言語ではサーバー側で受け付けない。画面上も承認ボタンを出さず、下書きの閲覧・編集だけできるようにする。
- DB の CHECK 制約と `SUPPORTED_LOCALES` は変えない。下書きの保存と、将来の再開に使う。

## 5. フェーズ3 の Exit の変更

旧: 同一議案を7localeで表示できる。

新: 議案を日本語・英語で表示でき、5言語の案内ページが公開されている。英語以外の翻訳が公開されない。

## 6. 再検討する条件

ある言語で、議案の翻訳を継続して確認できるネイティブ話者が確保できた場合は、その言語を `PUBLIC_TRANSLATION_LOCALES` に加えることを検討する。そのときは確認の体制（誰が、どの頻度で、日本語の変更にどう追随するか）をこの文書の後継として記録してから加える。
