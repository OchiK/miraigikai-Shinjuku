# AI Chat Policy

## MVP UX

トップページの汎用チャットより、各議案ページの「この議案についてAIに質問」を優先する。

例:
- 何が変わるの？
- 自分の生活に関係する？
- やさしい日本語で説明して
- Englishで説明して
- この金額は何に使われる？

## 入力コンテキスト

優先順位:

1. 当該議案の公式日本語資料
2. 新宿区の公式な概要
3. 当該議案のcanonicalな日本語説明
4. 必要な場合のみ公式関連資料

原則として、一般Web検索を答えの主要根拠にしない。

## 回答ルール

- ユーザーが使った言語で回答
- 根拠となる公式URLを表示
- AI生成であることを明示
- 根拠が足りない場合は「資料からは確認できない」とする
- 数字・日付・対象者条件を勝手に推測しない
- 事実と解説を区別する
- 議員・会派・政党・候補者の支持や不支持を勧めない
- 政治的な「良い/悪い」「最善/最悪」の総合判定をしない
- 選挙の勝敗予測をしない
- 公人の動機・健康・能力を推測しない
- 賛否がある論点では、確認できる立場や根拠を区別して説明する

## Scope guard

議会と無関係な質問はLLM呼び出し前に弾く。

例:
- 天気
- 一般的な宿題
- コーディング
- 雑談

返信:
「このチャットは新宿区議会の掲載案件について説明するためのものです。」

## コスト制御

川崎版に既にあるenvを利用する。

```env
CHAT_DAILY_USER_COST_LIMIT_USD=0.25
CHAT_DAILY_TOTAL_COST_LIMIT_USD=1
CHAT_MONTHLY_TOTAL_COST_LIMIT_USD=10
```

これは初期値の提案。実利用を見て調整する。

追加候補:
- 1ユーザー10質問/日
- 最大出力500〜800 tokens程度
- 同一質問のキャッシュ
- bot/rate limit
- 管理画面に月間利用額表示

## コスト観

このプロジェクトではAPI単価そのものより、以下の方が重要。

1. 公式サイト変更への追従
2. データ更新失敗
3. AI要約の誤り
4. 翻訳のstale化
5. bot abuse

AI利用料は上限をコードで固定し、予算事故をシステム的に防ぐ。
