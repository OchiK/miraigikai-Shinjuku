# Phase 7-C 議案・賛否・議員の相互連携導線 設計書

## 1. 概要と目的

「みらい議会＠世田谷区」の議員・議案連携モデル（世田谷モデル）に基づき、議案詳細画面（`/bills/[id]`）と議員画面（`/councilors`, `/councilors/[id]`）の間で、区民が「どの議員・会派がこの議案に関わったのか」「この議員はどんな議案を審議・質疑したのか」を直感的に行き来できる双方向のナビゲーション導線を構築する。

---

## 2. 画面別機能要件

### 2.1 議案詳細画面（`/bills/[id]`）
1. **会派賛否からの議員一覧連携**:
   - `FactionStanceCard` 内の各会派名（または行全体）から、議員一覧ページの該当会派アンカー（`routes.councilors()#faction-{faction.name}`）へのリンク導線を設置。
   - 会派別賛否データが未登録（または全会一致で原案可決）の議案であっても、「この議案を審議・議決した新宿区議会議員（38名）一覧へ」の自然な案内リンクを設置。
2. **議案に関連する議員の質問・発言セクション（`BillRelatedQuestions`）**:
   - 当該議案に関連付けられた質問（`council_member_questions.bill_id === bill.id`）が存在する場合、「この議案に関する議員の質問・発言」セクションを表示。
   - 質問タイトル、質問議員名（議員詳細へのリンク）、要約抜粋、会議録一次情報リンクを表示。

### 2.2 議員詳細画面（`/councilors/[id]`）
1. **「掲載中の質問」カードからの議案リンク**:
   - `CouncilorQuestionCard` において、`question.billId` が存在する場合、「関連議案: {bill.title} →」（`routes.billDetail(billId)`）へのリンクバッジを表示。
2. **所属会派が審議した議案への導線**:
   - 「この議員について」セクションの会派欄およびヘッダー等から、当該議員の所属会派が審議した定例会の議案一覧（`routes.sessionBills(sessionSlug)`）への導線を設置。

### 2.3 議員一覧画面（`/councilors`）
1. **会派アンカーの設置**:
   - `CouncilorListView` の各会派セクションに `id="faction-{faction.name}"` および `scroll-mt-20` を付与し、議案詳細や外部からのハッシュリンクで該当会派へスムーズにスクロール・着地できるようにする。

## 3. データフローとコンポーネント構成

```mermaid
graph LR
    subgraph 議案詳細画面 (/bills/id)
        BD[BillDetailLayout]
        FSC[FactionStanceCard] -->|会派クリック| CL[議員一覧 #faction-xxx]
        BRQ[BillRelatedQuestions] -->|議員名クリック| CD[議員詳細 /councilors/id]
    end

    subgraph 議員詳細画面 (/councilors/id)
        CDL[CouncilorDetailSection]
        CQC[CouncilorQuestionCard] -->|関連議案バッジ| BD
        CDL -->|審議議案リンク| SB[定例会 議案一覧 /sessions/slug/bills]
    end
```

## 4. UI/UX・アクセシビリティ（WCAG 2.2 AA / Organic）
- **カラー・トークン**: `globals.css` のみを使用（`text-mirai-accent-text`, `bg-card`, `bg-mirai-surface-sunken` 等）。
- **タップ領域**: すべてのリンク・ボタンで最小 44px（`min-h-11`）を確保。
- **アクセシビリティ**: リンクには適切な `aria-label` または明瞭なテキストラベルを付与。スクリーンリーダーで文脈が把握できるようにする。

## 5. 実装時レビューで変えた点（2026-09-25）

実装前に既存コード・スキーマ・ローカルDBと突き合わせ、次の点を設計から変えた。

1. **質問↔議案の紐づけデータが無い。** `council_member_questions.bill_id` はシード・本番インポーターとも設定しておらず、ローカル124件すべて null。代表質問・一般質問は特定の議案に対するものではないため、機械的な紐づけ（タグ一致など）はしない。表示側（議案詳細の質問一覧、質問カードの関連議案リンク）は実装し、データが入った時点で出るようにした。紐づけは委員会質疑の取り込み時に会議録の議題から行う。
2. **会派賛否は未投入。** 一次情報が無いため seed は会派見解を入れていない（`packages/seed/main/data.ts`）。`FactionStanceCard` は賛否がある議案か `preparing` の議案にしか出ないため、議員一覧への導線をカード内に置くとほぼ表示されない。導線は常設の新節「この議案と議員」（`BillCouncilorsSection`、§9 の 7 と 8 の間）に移し、会派名リンクだけカード内に置いた。
3. **「38名が議決」とは書かない。** 議長は慣例上採決に加わらないため人数を出さず、「議案は区議会の本会議で採決されます」とした。
4. **会派アンカーは slug（`factions.name`）で作る。** 議員側の `CouncilorFaction` に `slug` を追加し、`getFactionAnchorId` / `getFactionCouncilorsHref`（`councilors/shared/utils/faction-anchor.ts`）で議案側と揃えた。固定ヘッダー（約80px）に潜らないよう `scroll-mt-28`。
5. **定例会 slug を直書きしない。** 議員詳細の議案一覧リンクは `getActiveCouncilSession()` から作る（`"r8-2"` 固定にしない）。
6. **英語表示。** 議案詳細は ja/en の UI 文言を持つため、新節の文言を `ui-messages.ts` の `billCouncilors` に追加。質問本文は DB のまま日本語で出し、英語表示ではその旨を案内する。
7. **キャッシュ。** 質問の関連議案は公開中の議案だけ持つため、議員詳細と議案別質問のキャッシュに `bills` タグも付け、管理画面で公開状態を変えたときに作り直す。議案別質問の取得失敗は議案ページ全体を落とさず空にする。

既知の制約: 会派賛否が、所属議員のいない会派（本番に残る旧4会派など）を指す場合、会派名リンクは議員一覧の先頭に着地する。賛否データを投入する際に確認すること。
