# 翻訳およびルビ手動確認・編集機能（Translation & Ruby Review Tooling）要件定義

## 1. 背景と目的

「みらい議会＠新宿区」では、行政・議会情報をあらゆる住民に届けるため、以下の2つのアクセシビリティ施策を進めている：
1. **多言語翻訳（Phase 3）**: 英語、中国語簡体字、韓国語、ネパール語、ミャンマー語、ベトナム語の6言語展開。
2. **やさしい日本語・ルビ表示（Phase 2）**: 行政用語の平易化、および Rubyful V2 による自動ふりがな（ルビ）表示。

しかし、以下の運用上の課題が存在する：
- **翻訳の確認・承認の難しさ**: AIが下書き生成した翻訳（`status = 'generated'`）を公開するには、人の目による確認（`reviewed` への昇格）が必須。現在、管理画面に原文（日本語）と各言語の翻訳文を横並びで突き合わせて確認・編集・承認するUIがない。
- **stale（陳腐化）差分の把握**: 日本語原文が改訂された際、`source_hash` の不一致により公開画面では自動フォールバックされるが、レビュアーが「どの部分が改訂されたのか」「再翻訳がどこに必要か」を視覚的に差分比較できない。
- **ルビの誤読・固有名詞の課題**: Rubyful V2 による機械的な形態素解析・読み付与では、地名（例: 角筈、落合、百人町）、議員名、議会・行政専門用語（例: 専決処分、付託、補正予算）などで誤読が発生するリスクがある。また、やさしい日本語の表記ルール（初出のみふりがな・言いかえ、2回目以降は漢字のみ）との整合性を手動で確認・補正する手段が不足している。

本ドキュメントは、管理画面（`admin/`）等において、**翻訳およびルビを手動で容易に確認・編集・承認できる仕組み**の機能要件と設計を定義する。

## 2. 機能要件

### 2.1 翻訳手動確認・編集機能（Translation Review & Edit）

| ID | 機能名 | 要件内容 |
|---|---|---|
| TR-1 | 原文・翻訳対照表示 | 日本語原文（難易度別: やさしい／ふつう／くわしく）と対象ロケール（en, zh-Hans, ko, ne, my, vi）を横並び（side-by-side）で並列表示する |
| TR-2 | 多言語手動編集 | タイトル、要約、本文の翻訳テキストを直接編集・修正できる |
| TR-3 | ハッシュ・stale状態検知 | 最新の日本語原文から計算した `source_hash` との一致・不一致（stale状態）をバッジおよび警告で明示する |
| TR-4 | 原文差分（diff）表示 | 日本語原文が変更された場合、前回翻訳時からの変更差分をハイライト表示し、再翻訳が必要な箇所を特定できるようにする |
| TR-5 | 承認ステータス管理 | `status` を `generated` から `reviewed` へワンクリックで承認更新できる。承認者（`reviewed_by`）および日時（`reviewed_at`）を自動記録する |
| TR-6 | キャッシュ即時無効化 | 翻訳の更新・承認保存時に、公開側の `CACHE_TAGS.BILLS` を自動 revalidate し、古い翻訳や下書きが残り続けないようにする |
| TR-7 | 一括確認ダッシュボード | 会期内の議案全件について、言語ごとの翻訳ステータス（未生成／generated／reviewed／stale）をマトリクス一覧表示する |

### 2.2 ルビ（ふりがな）手動確認・編集機能（Ruby & Furigana Tooling）

| ID | 機能名 | 要件内容 |
|---|---|---|
| RB-1 | ルビ適用プレビュー | 原文およびやさしい日本語本文に対し、ルビ（ふりがな）がどのように表示されるかを管理画面上でリアルタイムプレビューする |
| RB-2 | カスタムルビ辞書管理 | 新宿区の地名・施設名・議員名・議会用語について、単語単位の正しい読み（例: `角筈` → `つのはず`）を登録・管理する辞書マスターを整備する |
| RB-3 | 単語ルビ上書き指定 | 自動ルビ解析（Rubyful）に対して優先適用される単語上書きルールを定義・編集できる |
| RB-4 | 本文内インラインルビ支援 | やさしい日本語や本文内で、特定の語句に手動ルビ（`<ruby>漢字<rt>かんじ</rt></ruby>` または `［ふりがな］`）を付与・編集できる簡易エディタ支援を提供する |
| RB-5 | 誤読検知・辞書突合 | 登録された辞書やNG集に基づき、誤読されやすい漢字・用語が本文に含まれている場合に警告を表示する |

## 3. UI/UX 設計方針

### 3.1 画面構成案（Admin）

#### 1. 議案翻訳レビュー画面 (`/admin/bills/[id]/translations`)
- **上部ナビゲーション**:
  - 言語切り替えタブ: `[英語 (en)]` `[中国語 (zh-Hans)]` `[韓国語 (ko)]` `[ネパール語 (ne)]` `[ミャンマー語 (my)]` `[ベトナム語 (vi)]`
  - 難易度切り替えタブ: `[やさしい]` `[ふつう]` `[くわしく]`
  - ステータスバッジ: `● reviewed（公開中）` / `▲ generated（要確認）` / `✖ stale（原文変更あり）`
- **対照ペイン（Side-by-side Layout）**:
  - **左側（正本・日本語）**:
    - タイトル、要約、本文（読み取り専用、変更箇所がある場合は diff 表示）
    - 原文ハッシュ値（NFC SHA-256）
  - **右側（翻訳編集ペイン）**:
    - タイトル入力フィールド
    - 要約テキストエリア
    - 本文 Markdown テキストエリア
    - AI再生成ボタン（任意）
- **アクションバー**:
  - `[変更を保存（下書き）]`
  - `[確認済みにする（公開承認）]`
  - `[承認を取り消す（generatedに戻す）]`

#### 2. ルビ確認・辞書管理画面 (`/admin/ruby-settings` および `/admin/bills/[id]/ruby`)
- **ルビプレビューモード**:
  - 通常表示モードとルビ展開モードをトグル切り替え可能
  - 辞書で上書きされた箇所、自動推定箇所を色分け表示
- **カスタムルビ辞書一覧**:
  - 単語（表記）、読み（ひらがな）、カテゴリ（地名／人名／議会用語／一般）
  - CSV エクスポート／インポート対応

## 4. データモデル拡張案

### 4.1 カスタムルビ辞書テーブル（案）

```sql
create table ruby_dictionaries (
    id uuid primary key default gen_random_uuid(),
    surface_form text not null,       -- 表記（例: "角筈", "落合"）
    reading text not null,            -- 読み（例: "つのはず", "おちあい"）
    category text not null default 'general', -- 'place', 'person', 'council', 'general'
    priority integer not null default 0,      -- 優先度（高いものが優先）
    is_active boolean not null default true,
    created_at timestamptz not null default now(),
    updated_at timestamptz not null default now(),
    unique(surface_form)
);

alter table ruby_dictionaries enable row level security;
```

### 4.2 翻訳履歴・差分追跡（`bill_content_translations` の活用）
既存の `bill_content_translations` テーブルの列を活用：
- `status`: `'generated' | 'reviewed' | 'stale'`
- `source_hash`: 原文ハッシュ（`v1:sha256(...)`）
- `reviewed_by`: 承認担当者メールアドレス
- `reviewed_at`: 承認日時

## 5. 段階的実装計画

### Phase A: 翻訳対照確認・手動編集・承認UI（最優先）
1. `admin/src/features/bills-edit/` または独立した feature として翻訳編集・対照画面を実装
2. 日本語原文と選択言語の並列対照表示、`source_hash` 照合判定の可視化
3. 編集内容の保存および `reviewed` 承認機能
4. 保存時の `revalidateTag(CACHE_TAGS.BILLS)` 連携

### Phase B: ルビプレビュー＆インライン編集支援
1. 議案編集画面におけるルビ表示プレビュー（Rubyful 連携または簡易ルビ表示）
2. 本文編集時のルビ記法入力補助（例: `<ruby>漢字<rt>かんじ</rt></ruby>` または `【漢字】［かんじ］`）

### Phase C: カスタムルビ辞書マスター＆自動適用
1. `ruby_dictionaries` テーブルの新設
2. Admin 辞書管理画面（一覧・追加・編集・削除）
3. 公開側（`web`）における辞書データの取り込みと Rubyful または SSR レンダリングでの読み優先適用
